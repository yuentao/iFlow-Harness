# 全面审查报告（iFlow Harness / 心流·驭光）

审查日期：2026-09-19
审查范围：协议层、Host 面板、shared reducer、扩展入口、webview UI、构建产物与清单

## 总体结论

代码整体质量显著高于仓库平均：关键路径（会话丢弃守卫、审批超时、diff 回退防伪造、增量快照锚定、进程生命周期）都有明确注释、实测依据（wire behavior）和对应单测，且几乎每个已知坑都留了注释。找出的问题大多是「边界没有被完全封住」或「多余抽象」，而非系统性缺陷。以下按严重程度分级。

---

## A. 边界 / 鲁棒性问题

### A1. 严重：信任边界不完整 + 无沙箱提示
- 代理路径解析只做「绝对路径直通、相对路径拼会话目录」，没有会话目录前缀校验，`..` 可上逃；文件写入回调整体缺少目录边界校验。AGENTS.md「安全与凭据」一节自述的 S1（CRITICAL）项仍未闭合。
- 未看到写文件 / 执行前对「操作目录在沙箱外」的确认，也未看到对外部命令类工具的沙箱提示——扩展跑在用户本机，CLI 的执行工具直接落在真实 shell。
- 即便补上目录前缀校验，执行类工具本来就能读写会话目录之外的任意路径，审批卡只是「告知 + 同意」。这个模型本身安全上可辩护，但需要在使用说明里讲清楚；目前没有。

### A2. 中等：NDJSON 帧上限 vs MCP 大工具结果
单帧上限为 8MB，注释理由是「JSON-RPC 信封远小于此」。但 MCP 工具结果（大文件读取、长 diff）可能超过该上限，此时整帧被丢弃，工具卡显示空。这不是错误路径，而是静默丢失边界。建议实测 CLI 在 MCP 大结果场景下的实际帧长度，若可行提高上限并记录日志。

### A3. 中等：dispose 与进行中的连接（connecting）未取消
- dispose 只清理 client / 面板 / 状态栏 / 日志通道；若此时有一次进行中的连接握手，其 Promise 仍被持有。握手完成后 store 已经销毁，后续取用会得到空引用并抛错。慢初始化场景下关闭窗口，节点进程可能泄漏到初始化超时才结束。
- 热重认证路径在拆掉旧 client 后，进行中的连接同样可能仍指向旧 client。
- 修复方向：dispose / 重连时显式作废进行中的连接，或让握手收尾处检查已销毁标志。

### A4. 中等：sendPrompt 的 call-site 竞态
聊天参与者入口以「发后不管」方式触发 sendPrompt；若期间发生新会话 / 配置切换，内部取到的会话 id 已是旧值，而 client 已换成新会话的 client，请求会发到不存在的会话上。现有「会话已替换」守卫会丢弃该错误（不标记错误状态），用户看到「无响应」且无法诊断。建议在丢弃分支补一条含原始错误的日志。

### A5. 低危：审批 / 提问卡的回答消息无服务端锁
快速双击时第二次消息到达时卡片已被清除，处理函数直接静默返回。webview 侧有乐观锁，但命令面板入口与直接 postMessage 可绕过。属防御性低危，可加一条日志。

### A6. 低危：附件选择器的超限图片被丢弃而非降级
超过图片大小上限的选中项当前是直接跳过，没有降级为普通文件附件，与代码注释声明的「降级为文件附件」不一致。用户侧表现为附件静默消失。

### A7. 低危：会话附件临时目录无清理
拖入文件被写入系统临时目录下的固定子目录，长期使用会积累残留，无清理机制。

### A8. 低危：配置文件的读-改-写非原子
写临时文件 → 删除原文件 → 重命名三步不是原子的，中途崩溃会留下孤儿临时文件或丢失改动。注释已说明「最坏只丢我们的指针更新」，可接受。

### A9. 低危：错误消息兜底序列化可能暴露原始信封
错误提取的最终兜底会把 JSON-RPC 信封（含 code / data）原样塞进用户可见的错误横幅，显示为畸形 JSON，体验不友好。不涉及凭据泄漏（该路径不写配置文件），但建议对用户可见文本做一层裁剪。

## B. 奥卡姆剃刀（WTF 密度检查）

### B1. 死代码（应删）
- 会话状态中的「标记工具取消」函数：只有定义与测试引用，宿主零调用。
- 「revealOutput」消息类型与对应处理分支：webview 侧无任何发送入口，纯死协议。
- webview store 注释中两处提到的「setDraft」：只存在于注释，不存在于任何消息联合类型。
- 工作区散落的未跟踪产物：构建输出目录、一份 CLI 内核原始文件、一张调试截图、一份会话导出 markdown、一个 0.1.0 时期的 VSIX 安装包。

### B2. 未兑现设置
- 「CLI 空闲回收时长」设置项在清单与两个语言文件中声明，但源码零引用（AGENTS.md 陷阱 #14 已如实记录，本次仅确认仍为空）。发布前应删除或实现。

### B3. 重复抽象 / 过度设计（可简化）
- 斜杠命令转义逻辑镜像了 CLI 的专有切分规则（近 70 行）。这是「必须兼容命令行行为」的合理实现，但未来 CLI 换解析规则就会漂移；应强调版本绑定。
- 三套会话状态重置逻辑（新会话 / 开始回放 / 结束回放）字段各不相同，容易互漂（1.1.x 已各修过一次），可收敛为带选项的单一重置函数。
- 可中断延迟用 100ms 轮询实现，纯定时器语义已足够；注释说明是为了更快响应取消，可辩护。
- 认证表单内有一份校验，凭据模块里又有一份校验，双份维护。

### B4. 文档与测试一致性
- 测试规模：7 个测试文件 / 191 个用例（截至 2026-09-19），与 AGENTS.md 声明一致。
- 版本对齐：package.json 与 CHANGELOG 顶部均为 1.1.2，一致。
- README 部分能力描述（如「消息编辑重发」）与 1.1.2 实际「已移除编辑重发入口」不一致，建议顺带校对（非本次范围）。

## C. 建议的措施（按优先级）

1. 【安全】在使用说明中明确「执行类工具可触达会话目录之外，建议在沙箱 / 容器中运行」；同时给代理路径解析加上级穿越与目录前缀校验（S1 未闭合项）。
2. 【修复】dispose 与热重认证路径显式作废进行中的连接，防节点进程泄漏（A3）。
3. 【修复】附件选择器的超限图片改为真正降级为文件附件，与注释一致（A6）。
4. 【修复】sendPrompt / 聊天参与者 / 重新生成在「会话已替换」丢弃分支补一条含原始错误的日志（A4）。
5. 【清理】删除死代码（取消标记函数、revealOutput 死协议）、构建产物与根目录遗留文件；实现或删除空闲回收设置项。
6. 【核实】跑一遍类型检查、单测与构建验证；用联调脚本实测 MCP 大工具结果的帧长度上限（A2）。
