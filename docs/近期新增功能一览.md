## 一、内置内核净化：只走显式配置的 API 端点

### 是什么

随包分发的内置裁剪 CLI 去掉了三类上游自带行为：

- OAuth 登录分支：移除 Google tokeninfo 校验与 `oauth-iflow` / `oauth-aone` 分支，鉴权统一为 OpenAI 兼容方式。
- 阿里侧遥测：移除 `log.mmstat.com` 的 cna/PV、`gm.mmstat.com` 的 AI tracking、`sunfire` OTel 与 `ducky` fetchModels。
- iFlow 云主机默认值与内部端点：移除 `cloud.iflow.cn` 插件下载、`platform.iflow.cn` 内建 `web_search` / `web_fetch`、iflow.cn 的 OAuth/userinfo/ad-phrases，以及 `apis.iflow.cn` 默认 baseUrl。

### 怎么用

- 首次使用按引导向导配置，或到「账户与模型」填写 OpenAI 兼容的 baseUrl + apiKey + modelName。
- 多个配置保存在内核 `~/.iflow/settings.json` 的 `apiProfiles` / `currentApiProfile`，面板凭据与共享 settings.json 相互隔离。
- 显式配置的 baseUrl 不受影响，即使它指向 iFlow 主机也照常使用。
- 上述三项剥离分别由环境变量 `IFLOW_OAUTH_STRIP` / `IFLOW_TELEMETRY_STRIP` / `IFLOW_INTERNAL_HOST_STRIP` 兜底，用于需要保留旧行为的排查场景。

### 注意点

- 升级提示：以前依赖 iFlow 官方 OAuth 登录的用户需改用 API 配置；内核不再保留可用的 OAuth 登录通道。
- 缺失 baseUrl 时直接报错，不再回退到 iFlow 云主机。
- 不再向 Google 发送 token、不再有 60s 认证超时、不再删改 `oauth_creds.json`。
- 该项属于 3.12.0 的「行为变更（重要）」，升级前请确认当前会话已有可用的 API 配置。

## 二、记忆能力

### save_memory 的 scope

- 是什么：内置保存记忆工具新增 `scope` 参数，取 `global`（默认，写用户级记忆）或 `project`（写当前工作区），与上游字节行为一致。
- 怎么用：在对话里让模型保存记忆并指定作用域，或用助手消息行内「记住这条」弹窗选择全局 / 项目；编辑器右键「记住选中内容」同样可写。扩展只做 loader 注入，写入委托内核，字节布局不漂移。
- 注意点：不传 `scope` 时按 `global` 处理；`project` 写入当前工作区；层级记忆仍加载 primary + 祖先 additional + 递归 hierarchy 的 `AGENTS.md` / `IFLOW.md`，面板读写的就是这些真正生效的文件。

### 记忆维护与自动整理

- 是什么：面板空闲时定期整理记忆的自动维护段，默认「只预览」不改文件。
- 怎么用：在设置中调整以下键：

| 设置键 | 默认值 | 说明 |
|---|---|---|
| `iflow.memoryMaintenanceEnabled` | `false` | 开启定时整理 |
| `iflow.memoryMaintenanceStrategy` | `report` | `report` 只预览 / `apply` 备份后改写 |
| `iflow.memoryMaintenanceIntervalDays` | `7` | 整理周期（天，1–90） |
| `iflow.memoryMaintenanceIdleMinutes` | `15` | 空闲多少分钟后才整理（1–240） |
| `iflow.memoryMaintenanceGlobalTokenBudget` | `4000` | 全局记忆自动维护段 token 上限（500–50000） |
| `iflow.memoryMaintenanceProjectTokenBudget` | `2500` | 每个项目记忆文件自动维护段 token 上限（500–50000） |
| `iflow.memoryMaintenanceTotalTokenBudget` | `12000` | 所有记忆文件自动维护段 token 合计上限（1000–200000） |
| `iflow.autoMemoryCapture` | `true` | 每轮结束后提取长期记忆候选，确认后才写盘 |
| `iflow.memoryExtractTimeoutSeconds` | `90` | 记忆提取最长等待秒数，0 = 不限（0–600） |

- 注意点：`apply` 策略会先备份再改写；自动提取的候选需用户确认后才写盘，最多 5 条并做去重与置信度门控。

### 立即整理记忆

- 是什么 / 怎么用：在命令面板（`Ctrl/Cmd+Shift+P`）执行 `iflow.curateMemory`（标题「立即整理记忆」）手动触发一次整理。
- 注意点：记忆整理等设置写入失败时会带上真实原因（只读 / JSON 损坏 / Settings Sync 冲突 / 旧版扩展），便于定位；想把「只预览」变成真正改写，需要先把 `iflow.memoryMaintenanceStrategy` 设为 `apply`。

## 三、超流体（Super Agent）

### 隔离与调度

- 是什么：主会话是协调者，把可独立完成并验证的工作单元写成任务书，**单层拆解**派发给超流体（子会话不再派发下级子会话）。每个超流体 = 独立 CLI 进程（各带 cwd 与凭据）+ 独立 ACP 会话 + 独立 git worktree / 分支（`iflow/super/<slug>-<unique>`），落在项目内 `.iflow/super/worktrees/`，由仓库本地 `.git/info/exclude` 排除，主工作区 git status 保持干净。
- 怎么用：顶栏「超流体」控件是看板入口，折叠时只报计数与待处理数，展开后逐行给出状态、分支与工作目录、汇报摘要，以及中断 / 合并 / 清理操作。超流体始终免确认（宿主直接放行权限请求与残留的 plan 退出事件），只有它真的需要你回答时才把提问推到看板就地作答。结束后由宿主**串行**把分支合并回来，合并前先用 `git merge-tree` 在对象库里预演。
- 注意点：合并只在会覆盖你未提交的改动、或仓库正处于 merge/rebase/cherry-pick 中途时才让路，绝不替你 commit / stash / 撤销本地改动；也可配成推送分支开 PR 或只保留分支由你在看板手动合并。worktree 只含已提交内容，主仓未提交 / 未跟踪文件对子会话不可见；免确认不提供沙箱，子会话能不经审批跑 shell。

### 独立 API 配置与模型（3.12.0）

- 是什么 / 怎么用：两个顶层设置让子会话按自己解析出的端点 / 凭据 / 模型 / 上下文窗口运行：

| 设置键 | 默认值 | 说明 |
|---|---|---|
| `iflow.superAgentProfile` | `""` | 超流体请求使用的 API 配置名，留空跟随主会话 |
| `iflow.superAgentModel` | `""` | 超流体请求使用的模型 id，留空用所选配置的模型名 |

- 设置页「超流体」下新增「API 与模型」分组；模型下拉按所选配置实时拉取 `/models`，带 loading / 空列表 / 真实错误 / 下架降级提示，请求带序号防止迟到回包串台。
- 注意点：两个键都不配置时与旧行为逐字段等价。派发时会校验模型是否已下架（4s 上限，失败 / 空不降级），降级仅提示、不改设置。

### 看板回填具名 API Profile（3.13.0）

- 是什么 / 怎么用：看板回填实际命中的具名 API Profile 名，直接展示「跑在哪个 API 配置」；它与 `spawnModel` 复用同一份 spawn 计划，不重复解析端点与模型。
- 注意点：零配置老用户的 `profileId` 保持未定义，看板逐字节不变，不需要为这项改动做任何迁移。

### 相关设置一览

| 设置键 | 默认值 | 说明 |
|---|---|---|
| `iflow.superAgent.integration` | `merge` | 完成后带回改动的方式：`merge` / `pr` / `manual`，合并前预演 |
| `iflow.superAgent.maxConcurrent` | `5` | 同时运行的超流体数量上限（1–20），超出 FIFO 排队，立即生效 |
| `iflow.superAgent.maxAttempts` | `2` | 失败后最多自动尝试次数（含首次，1–5） |
| `iflow.superAgent.dependencyPolicy` | `block` | 上游失败时依赖任务：`block` 跳过 / `continue` 照常执行 |
| `iflow.superAgent.fullTrust` | `false` | 完全信任：直接在主仓运行、保留全部工具与 MCP，谨慎开启 |
| `iflow.superAgent.keepWorktree` | `false` | 正常完成后是否保留工作目录；失败 / 中断始终保留 |
| `iflow.superAgent.maxWorktrees` | `10` | 磁盘最多保留的已结束工作目录数（0–100，0 = 不限），分支一律保留 |
| `iflow.superAgent.defaultWorkspace` | `""` | 未打开文件夹时的默认工作区，留空用 `~/.iflow/workspace` |
| `iflow.superAgent.childToolAllowlist` | `[]` | 限制超流体可用的内置工具名，留空不限制 |
| `iflow.superAgent.childMcpServerAllowlist` | `[]` | 限制超流体可访问的 MCP 服务器名，留空不限制 |

其中 `iflow.superAgent.maxAttempts` 与 `iflow.superAgent.dependencyPolicy` 自 3.11.4 起才真正下发给子会话调度（含取值钳制），此前只是 UI 上存在。

## 四、QQ 远程渠道

### 怎么用

在设置中调整以下键：

| 设置键 | 默认值 | 说明 |
|---|---|---|
| `iflow.qq.enabled` | `false` | 是否启用 QQ 远程任务通道 |
| `iflow.qq.allowedUsers` | `[]` | 允许提交任务的 QQ 用户 openid，留空不接受单聊任务 |
| `iflow.qq.allowedGroups` | `[]` | 允许提交任务的 QQ 群 openid，留空不接受群聊任务 |
| `iflow.qq.workspace` | `""` | 远程任务运行的工作区目录，须为当前工作区根，留空即当前根 |
| `iflow.qq.remotePolicy` | `supervised` | 远程策略：`readonly` / `supervised` / `trusted` |
| `iflow.qq.maxConcurrentTasks` | `2` | 同时运行的远程任务数（1–10） |
| `iflow.qq.rateLimitPerMin` | `6` | 每分钟最多接受的远程任务数（1–60） |
| `iflow.qq.resultDetail` | `standard` | 回传结果详细程度：`summary` / `standard` / `full` |
| `iflow.qq.autoMerge` | `false` | 远程任务完成后是否自动合并其分支 |

### 注意点

- `supervised`（默认）下工具调用需在 QQ 审批，4 分钟未响应按拒绝；`readonly` 只读取、写文件与执行命令被拒；`trusted` 无需审批，仅限完全掌控的账号与群。
- 工作区必须是当前工作区根，否则服务拒绝启动。
- QQ 设置统一写 Global（机器级能力，可被 Settings Sync 携带），写入时会清掉同键的存量 Workspace 覆盖，避免「显示与实际生效分裂」；解绑时设置写入失败会如实提示。
- 白名单 openid 建议不要提交到版本库。

## 五、效率模式 steady / turbo

- 是什么：提示词档位，含子会话，立即生效。
- 怎么用：设置键 `iflow.efficiencyMode`，取 `steady`（默认，默认规则）或 `turbo`（快速产出、减少探索）。
- 注意点：切换即时生效，同时作用于主会话与超流体；写入失败会带上真实原因提示。

## 六、多工作区根

- 是什么：会话级目标根子集（通过 `settings.add_dirs` 传入，只收紧不放宽）与 Composer 根选择器，根集合单一来源为 `workspaceRoots()`。
- 怎么用：在 Composer 用根选择器挑选目标根；上下文引用用 `@<根别名>/<路径>` 精确指定某个根下的文件，路径带 realpath 边界校验。`@` 触发的文件上下文还支持文件夹搜索、`@problems` 工作区诊断、`@git` status+diff、`@url:` 网页正文与 `@terminal` 终端记录。
- 注意点：`settings.add_dirs` 只收紧、不放宽，不能借它扩大会话可访问的工作区范围。该项为 3.11.0 引入的多仓库协作能力。

## 七、MCP

- 是什么：MCP 供超流体使用（主会话进程禁用 MCP、不带 MCP 工具）；目录卡片展示连接状态、工具 schema、prompts 与失败原因，配置编辑器表单化，支持全局 / 项目双作用域。
- 怎么用：在设置 → MCP 服务器管理查看与编辑，保存原子写回并可一键热重启；服务器模板按类别分组并标「推荐」，便于挑选。
- 注意点：连接失败时健康诊断按 `spawn_failed` / `timeout` / `protocol_error` / `network_error` 四类给出可操作引导，并提供刷新 / 修改配置入口；schema 超预算会给出阈值提示，broker 侧超过 4MB 时置位 `schemaOmitted`。持久化上，宿主写 `~/.iflow/settings.json` 改为 tmp + 原子 rename，CLI loader 读 / 解析失败时跳过写入，避免 `mcpServers` / `tokensLimit` / `language` / `approvalMode` 等键被剥光。模板分组、健康诊断与 schema 预算为 3.11.0 引入。

## 八、服务商预设清单加锁（3.13.0）

- 是什么：引导向导的提供商预设清单加锁，只列当前支持的第三方服务商，不含已下线的 iFlow 开放平台。
- 怎么用：首次配置 API 时在引导向导选择预设，或到「账户与模型」切换预设（切换预设不继承旧网关模型名）。
- 注意点：用户已保存的、指向 iFlow 主机的 Profile 保持自定义端点，不映射也不改写，升级不会动已有配置。

## 十、快速上手路径

1. 点击状态栏心流状态项打开面板（也可执行 `iflow.openPanel` 或点击编辑器标签栏图标）。
2. 首次使用按引导向导配置 API 凭据，OpenAI 兼容的 baseUrl + apiKey + modelName 缺一不可。
3. 输入消息开始对话；工具调用在面板中请求审批，Diff 卡片支持逐块保留 / 回退，用户气泡可回滚到此轮。
4. 需要模型窗口与单价数据时，到设置「账户与模型」点「联网补充模型数据」，宿主检索后由当前模型提炼并逐条溯源校验。
5. 记忆整理与会话导出可从命令面板执行，包括 `iflow.curateMemory`、`iflow.restartCli`、`iflow.exportSessionMarkdown`、`iflow.exportSessionJson` 与 `iflow.exportWireLog`。

> 安全与信任边界：内核执行类工具运行在本机真实 shell 中，审批卡是「告知 + 同意」而非沙箱；超流体免确认同样不提供操作系统级隔离。请在信任的项目中使用，处理不信任代码库时建议在容器 / 虚拟机中运行 VSCode。
