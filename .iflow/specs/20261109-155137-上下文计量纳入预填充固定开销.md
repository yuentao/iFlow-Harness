## 上下文计量纳入预填充固定开销

### 问题
占用条在 **host 估算路径**下只统计转录块，每次请求都携带的固定预填充（系统提示词 / 内置提示 / 记忆 / 工具声明）完全没算 → 占用被系统性低估。实测内核请求固定输入 ~61K tokens（system ~40K + tools schema ~12K），而面板可能只显示几千。

### bundle 实证（`J:\git\iflow-fork\reverse\iflow.readable.js`）
- `startChat()`：`d` = 系统提示词（内核模板 + 我们的覆盖模板 + 层级记忆 + 上下文文件），`u = [{ functionDeclarations: a }]` = 工具声明 —— 两者每次请求都带上。
- acp-context-report Mod 的报告**只有** `systemPrompt`（逐字节，见 `bundle/acp-context-report-loader.cjs`）；工具声明只能经 mcp-status Mod 拿到 **MCP 部分**，内核内置工具声明 wire 上无通道。
- 压缩的 `newTokenCount` = `countTokens({model, contents})`（CompressManager.tryCompress）—— **只算历史，不含系统提示词与工具声明** ⇒ 预填充加在折叠之外不会与 floor 双计。

### 改动
1. **`shared/messages.ts`**：`SessionUsageUi.prefillTokens?`、`UsageBreakdownUi.prefill?`。
2. **`shared/session-state.ts`**
   - 新增 `injectedPrefillTokens()`：取注入卡缓存的 token 总量（缺失时按 items 重算一次并回填）。
   - `estimateSessionUsage()`：预填充计入 `inputTokens` + `breakdown.prefill`，**加在压缩折叠之外**（系统提示与工具声明不随 `/compress` 消失）。
   - `recountBlockTokens()`：注入卡正文不可变，保留已计量的预填充（不再被清零）。
   - `blockTokens()`：注入块仍返回 0 ⇒ 权威路径的 delta 不会重复计入。
   - `refreshSessionUsage()`：权威路径**不再叠加**预填充（`lastRequestInputTokens` 已含全部固定开销）。
3. **`webview/src/components/Composer.tsx`**：tooltip 增「预填充 N tokens（系统提示词 / 记忆 / 工具声明）」。
4. **`webview/src/store.ts`** mock：补预填充字段（保持 mock 数值自洽）。
5. **测试**：改写「excludes injected bodies…」（行为已反转）、新增「预填充不随压缩折叠消失」「权威路径不双计」「预填充计入输入与占用」。

### 诚实边界（写进注释与文案）
host 估算 = 系统提示词 + 记忆 + 上下文文件 + 知识库 + MCP 工具声明，**不含**内核内置工具声明与环境目录清单（wire 不可得）⇒ 估算值是下界；内核上报路径含全部。
