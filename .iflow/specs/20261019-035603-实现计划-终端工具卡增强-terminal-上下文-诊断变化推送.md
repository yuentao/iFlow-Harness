## 实现计划：终端工具卡增强 + @terminal 上下文 + 诊断变化推送

### 背景结论（评估部分）
- **「dev server 持续输出订阅」**：CLI 自跑的 shell 无法附着（子进程随工具调用结束）。可行形态 = 用 VS Code **Shell Integration 执行 API**（1.93 定稿；engines ^1.90 → 运行时探测 + 本地结构类型，不 bump engines/@types）增量消费 `execution.read()`：长进程记录**边跑边增长**，@terminal 可注入仍在运行的 dev server 最新输出。
- **「诊断自动推送进行中会话」**：ACP 无轮中注入通道（每轮只接受一次 session/prompt），真·自动推送协议上不可行。保守落地 = 流式期间监听 `onDidChangeDiagnostics`，错误数较轮次基线上升 → 每轮一次 sticky toast「排队修复」，点击后携带新 @problems 卡入队（空闲则直发），**绝不静默自动发送**。

### 改动清单
1. **shared/context-source.ts**：`CONTEXT_CHAR_LIMITS.terminal=32K`；`TerminalCommandEntryUi` + 纯函数 `buildTerminalReport`（`$ cmd` + cwd/退出码/运行中 + 尾部保留输出 + 截断计数）。
2. **shared/session-state.ts**：`extractRerunnableCommand(input)`——识别 `capToolInput` 截断（长度 = MAX+1 且尾 "…"）返回 null，防止重跑半截命令。
3. **shared/messages.ts**：`ContextKind` += `"terminal"`；`WebviewToHost` += `{ type:"runInTerminal"; toolCallId; execute:boolean }`。
4. **src/panel/terminal.ts**（新）：`TerminalRecorder`（事件源可注入便于单测；环形 20 条、单条输出 64K 尾部保留、start 增量消费/end 兜底补读、exitCode/running）+ 单例 `getTerminalRecorder()` + `openInTerminal(command,cwd,execute)`（复用命名 "iFlow" 终端、cwd 变化先 cd、execute=false 预填不回车）。
5. **src/panel/panel.ts**：
   - 路由 `runInTerminal` → 校验 toolKind execute/run_shell_command + `extractRerunnableCommand`，失败 toast；
   - `resolveContext` 增加 terminal 分支（不可用/空记录给引导性错误）；`contextSectionTitle` 增加 terminal；problems 分支抽 `collectProblemsBody()` 复用；

6. **src/extension.ts**：activate 时附着 recorder（面板未开也捕获）。
7. **webview**：MessageList ToolCard 对 execute 卡加两个图标按钮（SquareTerminal 预填 / Play 重跑）；Composer KEYWORD_SOURCES 加 `@terminal`（含两处点击/回车分支、卡片图标、placeholder 文案）；i18n.ts 补英文条目。
8. **l10n/bundle.l10n.en.json** + **test/vscode-stub.ts**（补 `languages`、`DiagnosticSeverity`、`window.terminals/createTerminal`）。
