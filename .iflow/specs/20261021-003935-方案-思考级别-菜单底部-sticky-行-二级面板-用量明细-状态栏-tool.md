## 方案：思考级别 = 菜单底部 sticky 行 + 二级面板；用量明细 = 状态栏 tooltip

### 1. 模型菜单（Composer.tsx）
- **移除**菜单内「思考级别」分区与 `<UsageSummary />`，菜单回到「搜索框 + 模型列表」的纯列表。
- **底部 sticky 行**：`[图标] 思考级别   深度 ›`，`sticky bottom-0` + 底色/毛玻璃/上边框，无论模型列表多长都固定在可视底部（贴在菜单内，不是追加在列表尾部）。
- **二级面板**：点击该行就地展开——`‹ 思考级别` 返回行 + 4 个级别（名称 + 说明 + 当前勾选），选中即 `setThink` 并关闭菜单。
  - 展开时焦点落到第一项（Dropdown 只在打开瞬间聚焦，新增项需显式接管），返回时焦点还给 footer 行；ArrowUp/Down 仍由 Dropdown 的 menuitem 遍历覆盖。
  - 面板高度 ≈ 184px，在菜单 `max-h: 22rem` 内，超出部分由列表滚动吸收，不改变菜单外框。
- 新增 `thinkPanel` state，随菜单打开/关闭重置。

### 2. 用量（Composer.tsx + panel.ts）
- 删除 `UsageSummary` 组件、菜单内挂载点，以及仅它使用的 3 个 i18n 键（"用量" / "上下文 {0} / {1}（{2}%）" / "上下文约 {0} tokens"）。
- 模型 chip 保留紧凑读out：占用条 + `1%` + 成本，悬停走既有 `usageTooltip`（零新增控件）。
- **明细挪到「会话信息处」**：`updateStatusBar`（每次状态推送都调用，无需新订阅）给状态栏 tooltip 追加会话用量块——上下文 x/y（p%）、输入/输出、缓存读取、分项、预估成本；状态栏文字保持不变，避免常驻噪声。用 `MarkdownString` + `vscode.l10n.t` 文案。

### 3. 验证
- `cd webview && npx tsc --noEmit`、`npm run typecheck`、定向 vitest、`npm test`
- webview 构建 + 静态服务；frontend-tester 目验：长模型列表下 footer 常驻可达、二级面板焦点与选中、窄宽（300/360px）不溢出、菜单滚到底部仍可见
