# 修复超长问答卡超出显示范围

## 根因
- `QuestionCard` 正文滚动上限是 `max(140px, 100vh−240px)`（按视口猜测预算）。
- 卡片实际住在 transcript 容器的底部浮层里，容器高度 = 视口 − header − Composer − 状态栏，且 Composer 可拖拽变高；卡片自己的 header/倒计时/操作行约 110px 也不在 240px 预算内。
- 结果：整卡高于容器，向上越过面板 header（截图里 header 被卡片盖住），底部「提交回答」被挤出可视区。

## 改动（2 个文件）
1. **`webview/src/App.tsx`**
   - pending 浮层从 `inset-x-0 bottom-0`（高度随内容）改为 `inset-0 + justify-end`（铺满容器、底锚）——容器高度确定，卡片才能用 `max-h-full` 锚定。
   - `--pending-card-h` 测量改为「容器高度 − 最上卡片 offsetTop」（overlay 现在恒等于容器高，直接量 overlay 会给出整容器高度，MessageList 底部留白会错）。ResizeObserver 同时观察 overlay 与各卡片。
2. **`webview/src/components/QuestionCard.tsx`**
   - 卡片根：`flex max-h-full flex-col`（上限锚定浮层容器）。
   - 正文：去掉视口 max-h，改 `min-h-0 flex-auto overflow-y-auto`（吃剩余空间、内部滚动）。
   - header / 倒计时（包一层 shrink-0）/ 操作行：`shrink-0`，保证按钮永远可见。
   - Approval/Plan 卡不动（本次只修问答卡；浮层底锚行为对它们不变）。

## 验证
- `cd webview; npx tsc --noEmit`
- `npx vitest run test/cards-shortcuts.test.tsx test/ui-kit-guard.test.ts`
- `npx vite build webview`
- frontend-tester 用 mock webview（serve 8791）实测超长双问题卡：正文内滚、header/提交按钮始终可见、窄屏无横向溢出。
