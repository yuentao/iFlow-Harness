## 目标
1. 主会话只做任务委派：生成中用户按 Enter 不再入队排队，直接派发成子会话。
2. 子会话汇报**异步并行**：走独立直连模型调用（`streamChatCompletion`），与主会话 ACP 轮次完全无关，不排队、不等待、不丢失。

## 现状
- `panel.ts:7643` — `sendPrompt` 在 `status === "streaming"` 时 `enqueuePrompt(...)` 入队（排队来源）。
- `panel.ts:6113-6136` — `queueSuperReport` 把汇报塞进 `pendingSuperReports`，`flushSuperReports()` 在主会话忙时**直接 return**，等空闲才以 `internal:true` 的 prompt 发给主会话。这就是「排队/等待」。
- `panel.ts:2293` — `completeInternalPrompt` 已封装直连调用（凭据链 + 模型 + salvage），但受 `internalPromptBusy` 单车道限制（`runInternalPrompt` 会 return null）。

## 改动
### 1. `src/panel/panel.ts` — 汇报改走独立并行直连
- `queueSuperReport(entries)`：不再 push 到 `pendingSuperReports`，改为**立即** `void this.relaySuperReport(entries)`（fire-and-forget，不 await、不阻塞子会话状态机）。
- 新增 `private async relaySuperReport(entries): Promise<void>`：
  - 拼 `this.superAgent.reportPrompt(entries)` 得到上报文本；
  - 调 `this.completeInternalPrompt(text, SUPER_REPORT_TIMEOUT_MS, SUPER_REPORT_IDLE_MS)`（**绕过 `internalPromptBusy` 单车道**，因此与 enhance/标题/下一步等内部调用并行；各自独立 HTTP 请求）；
  - 成功后把模型回复作为一条**助手文本块**追加到主会话转录：新增 store 方法 `appendRelayMessage(text)`，内部 `state.blocks.push({ kind: "text", id: nextBlockId(), text })` + `noteMutationIndex` + `flush()`（走 blockPatch 增量，不触发新轮次、不改 `status`、不拍 checkpoint、不改会话标题）。
  - 失败（`null`）只 `log.warn`，**不重试、不丢给用户**；子会话状态本身已在 `superSessions` 看板里，汇报只是主会话的旁注。
- 删除 `pendingSuperReports` 字段、`flushSuperReports()` 方法，以及 `panel.ts:7817` 的调用点。
- `sendPrompt` streaming 分支：
  - `internal === true` 直接 `return`（宿主汇报不再走主会话轮次；理论上已无调用方，保留防御）。
  - 用户输入：拼 `contextBlock + trimmed` 为 task，`normalizeSuperTitle(首行)` 作标题，`getSuperAgent().spawn({ title, task })`，toast「主会话正在生成，已把这条消息派发为子会话「…」」，return。
  - 不再调用 `enqueuePrompt`。

### 2. `src/panel/store.ts` — 新增追加助手文本的方法
- `appendRelayMessage(text: string): void`：push `{ kind: "text", id: nextBlockId(), text }`，`noteMutationIndex`，`flush()`。

### 3. `webview/src/components/Composer.tsx`
- `enqueueMode` 语义改为「委派模式」：占位符「派发为子会话（Enter）」，按钮 title/文案「派发」，图标保留 `ListOrdered`。
- 移除 `<QueueStrip />` 渲染（保留组件定义与其 `queueEdited` 监听，避免守卫/类型连带失败）。

## 不改
- `shared/queue.ts`、`queueAction` 协议、`dispatchQueue`/`pauseQueueOnError` 保留（旧快照与其它路径仍可能带 queue）。
- `runInternalPrompt` 的单车道不变（enhance/标题仍互斥）；汇报走 `completeInternalPrompt` 直连，独立车道。
- 子会话 `spawn` 的 FIFO 与 4 并发上限不变。
